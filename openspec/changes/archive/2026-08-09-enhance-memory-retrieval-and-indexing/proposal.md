## Why

当前记忆系统已具备 SQLite 持久化、关键词召回、工作状态注入和轨迹分段等基础，但查询上下文仍是字符串拼接，Card 与 Episode 的索引维护主要依赖显式调用，也没有可降级的语义召回与确定性混合排序。下一阶段应先补齐“记忆如何形成、进入索引并被稳定召回”的工程链路，为长期个人助手建立可靠底座，而暂不引入反馈评测和在线学习闭环。

## What Changes

- 将用户当前输入、工作目标、当前步骤、会话与作用域约束建模为结构化记忆查询；用户输入保持主查询，工作状态只作为辅助上下文。
- 在现有 SQLite 关键词索引旁增加可重建的语义向量索引和待索引任务状态；原始 Claim、Card、Episode 与轨迹继续作为事实源。
- 使用“关键词 + 向量 + 元数据”多路候选、硬过滤、RRF 融合、稳定并列规则和按类型预算完成确定性混合召回。
- 增加受治理的 Card Builder：只从已生效且有证据的 Claim 生成或修订 Card，新版本可追溯，失败不破坏当前版本。
- 在完整轨迹提交后自动、幂等地生成带上下文前缀的 Episode 分段并登记索引；失败不影响原始轨迹和当前对话。
- 所有新增索引均支持版本识别、增量更新、全量重建和明确降级；不开启语义能力时保持现有关键词行为可用。
- 本 change 不包含用户反馈采集、LLM Judge、奖励建模、在线排序学习、自动强化、后训练，也不把 Reranker 作为首版必需能力。

## Capabilities

### New Capabilities

无。新增行为均属于现有 `memory` 能力边界。

### Modified Capabilities

- `memory`: 将现有关键词召回扩展为可降级的结构化混合召回，并补充 Card 自动投影、Episode 自动索引和语义索引生命周期要求。

## Impact

- 主要影响 `memoli_agent/memory/` 的查询模型、SQLite schema/store、检索器、Card/Episode 投影器及生命周期编排。
- 运行时仅增加内存生命周期调用点和诊断元数据，不改变串行 agent loop、工具协议或 provider 接口。
- `memory.db` 需要向前兼容的 schema migration；新增索引表是派生数据，可安全删除并重建。
- 语义模型作为可选配置和可替换接口接入；密钥不得写入数据库、轨迹或仓库配置。
- 保留现有 Markdown 迁移、关键词召回和工作 checkpoint 行为，并通过回归测试验证兼容性。
