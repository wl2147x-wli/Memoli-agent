## Why

Memoli 已经定义了 `ThinkingBlock`、Anthropic 签名解析和 `reasoning` 能力标记，但实际请求链路在 `invoke_provider` 重建 `ModelRequest` 时没有传入推理开关，因此 Reasoner 的常规调用无法真正启用模型推理。OpenAI 适配器仍以 Chat Completions 为主，只兼容性地读取流中的 `reasoning_content`，无法表达 Responses API 的推理项、加密续接内容及有序输出项；Anthropic 适配器虽然能够解析思考、签名和脱敏思考块，却缺少贯穿配置、路由、工具循环与上下文管理的统一续接合同。

当前 `ThinkingBlock` 还混合了承担不同安全责任的三类数据：允许用户查看的推理摘要、不得展示的隐藏推理，以及只应原样回传给同一提供商的协议续接数据。与此同时，路由器可能在一次工具循环中重新选择提供商，上下文编译、令牌估算与哈希使用的消息表示也不完全一致。这会造成推理配置失效、工具调用后的推理状态丢失、跨提供商误传私有状态，以及隐藏思维链进入日志、历史或界面的风险。

Codex 所依赖的 OpenAI Responses 协议和 Claude Code 所依赖的 Anthropic Messages 协议都表明：模型可见的协议续接状态必须与面向用户的进度、摘要和最终回答分离，并在工具往返过程中保持顺序与提供商亲和性。Memoli 需要建立同等清晰的边界，同时不保存、不展示也不伪造模型的原始思维链。

此外，已经归档的提供商变更描述了 `llm-providers` 行为，但规范事实源 `openspec/specs/` 中缺少该能力。代码、文档和 OpenSpec 之间已经发生漂移，后续修复缺少可验证的行为基线。

## What Changes

- 新增规范事实源中的 `llm-providers` 能力，恢复当前提供商基线，并明确推理配置、协议续接、流式事件、安全展示和降级行为。
- **破坏性变更**：把厂商私有的推理续接数据从通用 `ThinkingBlock` 和聊天历史中分离，建模为只能由对应适配器读取并原样回传的不透明续接状态；通用历史只保留文本、工具调用、工具结果以及明确允许展示的摘要。
- 修复配置到请求的传递链路，使模型配置中的推理开关、推理强度和展示策略能够进入 `ModelRequest`，并在发起网络请求前验证协议、模型能力与参数组合。
- 新增 `openai-responses` 协议适配器，支持 OpenAI Responses API 的有序推理项、函数调用项、标识符、阶段和加密续接内容；保留现有 `openai` 与 `openai-compatible` 的 Chat Completions 路径，并禁止根据模型名或地址隐式切换协议。
- 将一次“模型响应→工具执行→模型续接”建模为提供商交换。在交换结束前固定提供商、模型配置、协议和推理策略，避免路由器在工具循环中把私有续接状态发送给另一提供商。
- Anthropic 适配器必须按原始顺序、未经修改地回传当前工具循环所需的思考块、签名和脱敏思考块；OpenAI Responses 适配器必须按所选续接模式完整回传响应项。首版采用当前交换内的显式状态续接，不承诺跨轮次或进程重启恢复。
- 将跨提供商的用户展示策略统一为“隐藏、摘要、更新”三种语义。CLI 默认仅显示安全进度，不显示隐藏推理；只有显式启用时，才显示提供商明确标记为摘要或更新的内容。
- 统一上下文编译、令牌估算和哈希所依据的规范化消息表示；活跃交换的完整后缀不可被压缩或拆分，不透明续接状态不得进入通用压缩、归档、长期记忆或跨提供商降级路径。
- 增加协议级固定样例以及配置传递、工具循环、路由亲和性、流式顺序、上下文压缩、哈希一致性和无泄漏回归测试。

## Capabilities

### New Capabilities

- `llm-providers`：统一规定 OpenAI Responses、OpenAI 兼容 Chat Completions 与 Anthropic Messages 的推理配置、工具续接、流式事件、用量统计和安全边界。

### Modified Capabilities

- `agent-runtime`：增加提供商交换生命周期、路由亲和性、推理策略冻结，以及配置到请求的完整传递。
- `context-management`：统一消息的规范化表示，把活跃交换后缀作为不可拆分内容，并排除不透明续接状态的通用编译、压缩、持久化与跨提供商复用。
- `interactive-cli`：区分安全进度、提供商推理摘要与隐藏推理的展示语义，默认遵循最小披露原则。

## Impact

- 预计影响 `agent/llm/contracts.py`、OpenAI 与 Anthropic 适配器、路由器、`invoke_provider`、Reasoner 工具循环、上下文编译、配置加载、展示事件和相关测试；本制品更新本身不修改实现代码。
- 模型配置将增加明确的推理开关、推理强度和展示策略。旧配置保持推理关闭或使用协议自身的默认行为，不会因升级自动增加推理成本。
- `protocol = "openai"` 继续表示 Chat Completions 兼容路径；需要 Responses 推理与工具续接能力的工作负载必须显式选择 `protocol = "openai-responses"`。
- 不透明续接状态只存活于当前提供商交换，默认不进入 SQLite 轨迹、长期记忆、Hook 载荷、通用 JSONL 或跨提供商降级。本变更不承诺恢复因进程崩溃而中断的工具交换。
- 系统不得展示或保存原始思维链。可见内容只接受提供商明确标记的摘要或更新，以及 Agent 自己生成的安全进度说明，并继续执行长度限制和敏感信息处理。
