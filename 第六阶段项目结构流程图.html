一、项目装配结构

从左到右看：入口和配置创建 Runtime，Runtime 装配消息总线、agent 核心、pipeline、模型和工具系统。

入口与配置 Runtime 装配 消息总线 Agent 核心 Pipeline 阶段 模型推理 工具系统

启动入口

main.py 程序入口

启动 asyncio 主流程，调用配置加载，创建并运行 AppRuntime。

bootstrap/config.py load_config()

读取 config.toml；没有本地配置时使用默认配置。

总装配层

bootstrap/app.py build_app_runtime()

创建并连接 Bus、Provider、Reasoner、ToolRegistry、Pipeline、Runner、AgentLoop。

bootstrap/tools.py build_tool_registry()

创建 ToolRegistry，注册 time、calculator、memory、filesystem 等内置工具。

消息与通道

bus/events.py Message 类型

定义 InboundMessage、OutboundMessage；InboundMessage 提供 session_key。

bus/queue.py MessageBus

维护 inbound/outbound 两个异步队列，解耦 channel 和 agent。

channels/cli.py CLI Channel

读取终端输入，发布入站消息，等待并打印出站回复。

Agent 编排

agent/loop.py AgentLoop

消息泵：消费 inbound，调用 runner，发布 outbound。

agent/runner.py AgentRunner

消息路由器；当前把普通用户消息交给 PassiveTurnPipeline。

agent/core/passive_turn.py PassiveTurnPipeline

编排一轮被动对话：会话、上下文、推理、保存历史、生成回复。

推理与工具

Session + Context session.py / context.py

SessionManager 保存历史；ContextBuilder 构造模型 messages。

agent/core/reasoner.py Reasoner

调用 provider；如果模型返回 tool_calls，则执行一轮工具调用。

agent/provider.py LLMProvider

提供 EchoProvider 和 OpenAI-compatible provider。

agent/tools/*.py ToolRegistry

注册工具、导出 schema、执行工具，并把结果返回 Reasoner。

三、每个文件的职责对照表

模块 文件 功能说明
入口层main.py启动程序，加载配置，创建并运行 AppRuntime。
配置层bootstrap/config.py读取 TOML 配置，提供默认配置对象。
装配层bootstrap/app.py创建 MessageBus、Provider、Reasoner、ToolRegistry、Pipeline、Runner、AgentLoop。
通道层channels/cli.py负责命令行输入输出。
消息层bus/events.py / bus/queue.py定义消息结构和异步消息队列。
主循环agent/loop.py消息泵：消费 inbound，调用 runner，发布 outbound。
路由层agent/runner.py决定消息进入哪个 pipeline。
Pipelineagent/core/passive_turn.py编排一轮被动对话。
Lifecycleagent/lifecycle/*.py拆分 BeforeTurn、PromptRender、Reasoner、AfterTurn 等阶段。
会话agent/session.py保存多轮会话历史。
上下文agent/context.py构造模型 messages。
推理agent/core/reasoner.py调用 provider，并执行一轮 tool call。
模型agent/provider.py提供 EchoProvider 和 OpenAI-compatible provider。
工具agent/tools/*.py定义工具协议、注册表、内置工具和工具搜索。
工具装配bootstrap/tools.py注册 time、calculator、memory、filesystem 等内置工具。
第六阶段重点

模型可以通过 tool_calls 请求工具，Reasoner 执行一轮工具调用。

默认可运行

无 API key 时使用 EchoProvider，仍能完成 CLI 闭环。

工具边界

filesystem_read 只读取 workspace；memory 工具只是进程内临时记忆。

扩展方向

后续可接入长期记忆、插件工具、MCP 工具和 peer agent 工具。

主链路

CLI → Bus → Loop → Runner → Pipeline → Reasoner → Provider/Tools → CLI。
